# Runbook روز رویداد — میدان بنیان‌گذاران تپسل

مرجع سریع برای روز اجرای واقعی. جزئیات فنی هر بخش در `docs/ops.md` و
`deploy/README-deploy.md` است؛ این‌جا فقط چک‌لیست و اقدام است.

## پیش از رویداد (Pre-event checklist)

- [ ] آخرین کد با `deploy/deploy.sh` روی سرور دیپلوی و health-check
      (`curl http://89.42.199.174/api/phase`) سبز شده.
- [ ] `deploy/harden-server.sh` روی سرور اجرا شده (ufw/fail2ban/unattended-upgrades/SSH).
- [ ] سرویس `backup` بالاست و حداقل یک بک‌آپ موفق در لاگ دارد:
      ```bash
      docker compose ps backup
      docker compose logs --tail=5 backup
      ```
- [ ] یک بک‌آپ دستی تازه گرفته و به لپ‌تاپ کشیده شده (off-server، برای
      شبی که سرور کلاً در دسترس نیست):
      ```bash
      docker compose run --rm backup node /app/scripts/backup.mjs --once
      SERVER=root@89.42.199.174 KEY=~/.ssh/founders_arena ./deploy/pull-backups.sh
      ```
- [ ] یک تمرین ریستور (drill) روی staging یا یک کپی محلی انجام شده — نه
      روی دیتابیس واقعی رویداد.
- [ ] مانیتور uptime (UptimeRobot یا مشابه) روی
      `http://89.42.199.174/api/health` فعال است و یک هشدار تست دریافت شده.
- [ ] `scripts/reset-game.ts --yes` روی staging تست شده (نه production) تا
      مطمئن شوید قبل از شروع واقعی، اگر لازم شد، بازنشانی درست کار می‌کند.
- [ ] فاز بازی روی `REGISTRATION` است (یا هر فاز شروع برنامه‌ریزی‌شده).
- [ ] اعلانیه‌ها (Announcement) برای روز رویداد آماده و `active` هستند.
- [ ] تنظیمات اقتصادی در پنل `/admin` نهایی شده‌اند، چون بعد از `REGISTRATION`
      قفل می‌شوند: سکهٔ رایگان اولیه (`starting_coins`، پیش‌فرض ۲۰۰)، سقف اثر هر
      نفر روی حمایت مردمی (`support_cap`، ۵۰)، سقف خرید سکهٔ هر نفر
      (`max_bought_coins_per_user`، ۱۰۰۰)، قیمت‌های ثابت جایگاه تبلیغاتی و سقف هر
      تیم (`adslot_max_per_team`، ۲). `market_starts_at` (شروع جدول ساعتی
      جایگاه‌ها) را هم تنظیم کنید.
- [ ] تنظیمات زمان‌بند چک شده‌اند: `auto_auction=1` (شروع خودکار حراج بعدی صف)،
      `auction_gap_sec`، مدت فازها (`phase_hours_*`) و در صورت نیاز `auto_advance`.
- [ ] پرداخت خرید سکه آماده است (جزئیات در `docs/ops.md` بخش ۹):
      - در production، `PAYMENT_DRIVER` خالی یا `manual` است و
        `PAYMENT_FAKE_ALLOWED` تنظیم **نشده**.
      - متن راهنمای پرداخت دستی (شمارهٔ کارت/حساب و نحوهٔ ارسال رسید) در
        `/admin/coins` نوشته شده است.
      - یک خرید آزمایشی روی staging (با درگاه آزمایشی) از اول تا آخر انجام شده
        است.
- [ ] اگر این اولین دیپلوی پس از بازطراحی «همه‌چیز با سکه» است، پیش از آن بک‌آپ
      دستی گرفته‌اید. مهاجرت آن کیف بذر را به کیف سکه منتقل می‌کند
      (`docs/ops.md` بخش ۱۰).

## در حین رویداد (During the event)

- **دیپلوی فقط بین فازها انجام شود**، هرگز وسط یک فاز حساس (مخصوصاً
  `MARKET` که حراج‌های زنده داخل آن اجرا می‌شوند). حتی با `lb_try_duration`/
  `lb_try_interval` در Caddy (که تا ۳۰ ثانیه صبر می‌کند)، یک ری‌استارت
  کانتینر وسط حراج زنده تجربهٔ بدی می‌سازد. قبل از دیپلوی:
  1. مطمئن شوید در یک گپ بین فازها هستید (نه در حال شمارش معکوس یک حراج).
  2. `SERVER=... KEY=... ./deploy/deploy.sh` را اجرا کنید (build جدا از up
     است، پس داون‌تایم واقعی چند ثانیه‌ای).
  3. بلافاصله `curl http://89.42.199.174/api/phase` را چک کنید.
- بک‌آپ‌های خودکار هر ۱۵ دقیقه ادامه دارند؛ نیازی به کار دستی نیست مگر
  بخواهید قبل از یک عملیات پرخطر (مثل تغییر فاز یا اجرای settlement) یک
  بک‌آپ فوری بگیرید:
  ```bash
  docker compose run --rm backup node /app/scripts/backup.mjs --once
  ```
- اگر مانیتور uptime هشدار داد: اول `docker compose ps` و
  `docker compose logs --tail=100 web` را چک کنید (به `docs/ops.md` برای
  جزئیات نگاه کنید).

## کارهای برگزارکننده در هر فاز (جریان بازی)

فازها: ثبت‌نام و تیم → اتاق ایده → دور حمایت → ساخت محصول → روز بازار → پایان
بازی. فاز را از داشبورد `/admin` عوض کنید، یا با `auto_advance` بگذارید
زمان‌بند خودش پیش ببرد. فاز جداگانهٔ «حراج زنده» وجود ندارد؛ حراج داخل روز بازار
است.

### در تمام طول بازی: تأیید پرداخت‌های سکه (`/admin/coins`)

- با درایور `manual` هر خرید سکه یک سفارش «در انتظار» می‌سازد. پس از دیدن
  واریز یا رسید، سفارش را **تأیید** کنید. سکه‌ها همان لحظه به کیف بازیکن اضافه
  می‌شوند، بازیکن اعلان می‌گیرد و مبلغ به صندوق جایزه می‌رود. تأیید دوباره سکهٔ
  اضافه نمی‌دهد.
- اگر وجه نرسید یا مبلغ اشتباه بود، سفارش را با یک یادداشت کوتاه **رد** کنید.
- اگر بازیکنی پول داده ولی سفارشش «ناموفق» یا «لغوشده» مانده (مثلاً مشکل بازگشت
  از درگاه)، همان سفارش را تأیید کنید. سفارش تازه نسازید.
- سقف خرید هر نفر سفارش‌های در انتظار را هم حساب می‌کند. پس سفارش‌های باز را
  زود تعیین تکلیف کنید تا بازیکن پشت سقف گیر نکند.

### ثبت‌نام و تیم

- تیم‌ها ۱ تا ۳ نفره‌اند. «شرکت فردی» تیم یک‌نفره‌ای است که عضو تازه نمی‌پذیرد.
  سرپرست و رأی‌گیری وجود ندارد و هر عضو کارهای تیم را انجام می‌دهد.
- در `/admin/teams` می‌توانید عضو جابه‌جا کنید، تیم‌ها را ادغام کنید یا بی‌تیم‌ها
  را خودکار تیم‌بندی کنید.

### اتاق ایده و دور حمایت

- تحلیل‌گر هوش مصنوعی بعد از ثبت هر ایده برچسب «🤖 عالی / خوب / نیاز به کار»
  را می‌سازد. اگر کلید هوش مصنوعی نباشد برچسب نمایش داده نمی‌شود و بازی
  بدون آن ادامه پیدا می‌کند.
- در دور حمایت، بازیکن‌ها (حتی بی‌تیم‌ها) با سکه از ایده‌های دیگران حمایت
  می‌کنند. سقفی روی هر ایده نیست و سودی هم پرداخت نمی‌شود.

### ساخت محصول: درخواست‌های بازار استودیو (`/admin/studio`)

- تیم‌ها از صفحهٔ ساخت محصول، با لینک کد/بسته و توضیح، درخواست انتشار می‌دهند
  (در «ساخت محصول» و «روز بازار»).
- وضعیت هر درخواست را جلو ببرید: «در حال انتشار» ← «🚀 لایو» (لینک محصول
  منتشرشده لازم است). اگر درخواست مشکل دارد، «نیاز به اصلاح» را با یک یادداشت
  بزنید. تیم برای هر تغییر وضعیت اعلان می‌گیرد.
- فقط محصولات لایو نامزد جایزهٔ «بهترین محصول لایو» هستند. انتشار اختیاری است
  و مستقیماً امتیاز نمی‌دهد.
- فروش جایگاه‌های تبلیغاتی با قیمت ثابت از همین فاز باز می‌شود (اول‌آمده،
  اول‌برده؛ فقط برای تیم‌هایی که محصولشان را ثبت نهایی کرده‌اند).

### روز بازار: خرید و صف حراج (`/admin/auction`)

- بازیکن‌ها محصولات را به قیمت کامل می‌خرند. هر تیم نسخهٔ ویژهٔ محصولش را خودش
  به صف حراج می‌فرستد. صف ۲۰ دقیقه پیش از پایان روز بازار بسته می‌شود.
- با `auto_auction=1`، زمان‌بند حراج‌ها را یکی‌یکی به ترتیب صف شروع می‌کند و بین
  آن‌ها `auction_gap_sec` ثانیه فاصله می‌گذارد. مدت هر حراج خودکار کوتاه می‌شود تا
  کل صف در زمان باقی‌ماندهٔ فاز جا شود.
- دکمهٔ «ساخت صف حراج» همهٔ محصولات ثبت‌شده‌ای را که هنوز به صف نرفته‌اند، با
  ترتیب تصادفی به ته صف اضافه می‌کند. فقط اگر می‌خواهید همهٔ محصولات حراج شوند از
  آن استفاده کنید. با دکمهٔ شروع حراج بعدی هم می‌توانید صف را دستی جلو ببرید.
- برد حراج یک خرید حساب می‌شود و در امتیاز «حمایت مردمی» می‌آید.

### داوری (`/admin/jury`): پیش از پایان بازی تمام شود

- برای هر محصول به سه پرسش نمرهٔ ۰ تا ۱۰ بدهید: «آیا واقعاً کار می‌کند؟»، «ارزش
  واقعی برای کاربر یا گروه پگاه» و «تیزر و ارائه». نمرهٔ داور هوش مصنوعی جداگانه
  نمایش داده می‌شود و با نمرهٔ داوران مخلوط نمی‌شود.
- دو جایزهٔ انتخابی را تعیین کنید: «برترین کاربرد هوش مصنوعی» و «بهترین محصول
  لایو» (فقط از بین محصولات لایو). هر پروژه حداکثر یک جایزه می‌برد. اگر تیم
  انتخابی قبلاً جایزهٔ بالاتری برده باشد، این جایزه به او نمی‌رسد و پنل هشدار
  می‌دهد؛ در آن صورت تیم دیگری را انتخاب کنید.

### کسر امتیاز تقلب (`/admin/flags` ← `/admin/teams`)

- در `/admin/flags` تشخیص تبانی را اجرا کنید و پرچم‌ها را بررسی کنید. پرچم به‌تنهایی
  جریمه نیست.
- اگر تقلب تأیید شد، در `/admin/teams` برای همان تیم «کسر امتیاز» (عدد امتیازی که از
  کل کم می‌شود) و یک یادداشت دلیل ثبت کنید.
- برای بازیکن‌ها فقط همان یک متن ضدتقلب (`ANTI_CHEAT_STATEMENT`) را تکرار کنید
  و قانون تازه‌ای اعلام نکنید.

### پایان بازی و تسویه (`/admin/settlement`)

۱. پیش از رفتن به `CLOSED` مطمئن شوید همهٔ نمره‌های داوری و کسرهای تقلب ثبت شده‌اند،
   چون تسویه امتیازها را **یک‌بار برای همیشه** در `TeamScore` تثبیت می‌کند. سفارش‌های
   سکهٔ در انتظار را هم تعیین تکلیف کنید.
۲. یک بک‌آپ فوری بگیرید (دستور بالا).
۳. فاز را به `CLOSED` ببرید. حراج زندهٔ باقی‌مانده تسویه می‌شود، حراج‌های
   شروع‌نشدهٔ صف حذف می‌شوند و تسویهٔ نهایی خودکار اجرا می‌شود.
۴. اگر پنل خطای تسویه نشان داد، از `/admin/settlement` دوباره اجرا کنید. تسویه
   idempotent است و دوباره چیزی ثبت نمی‌کند.
۵. حالا جدول امتیازات به‌جای «تعداد حامی»، امتیاز کل، ریزامتیاز سه معیار و جوایز
   را نشان می‌دهد. جایزه‌های انتخابی داوران از روی انتخاب ثبت‌شده در `/admin/jury`
   نمایش داده می‌شوند.

## اقدامات حادثه (Incident steps)

### سایت پایین است / ۵۰۲ مداوم

```bash
ssh -i ~/.ssh/founders_arena root@89.42.199.174
cd /srv/arena/app
docker compose ps
docker compose logs --tail=200 web
docker compose logs --tail=50 caddy
```

اگر `web` کرش کرده: `docker compose up -d web` (بدون rebuild، سریع). اگر
مشکل از یک دیپلوی اخیر است، به کامیت قبلی برگردید و دوباره `deploy.sh` را
اجرا کنید.

### دیتابیس خراب/ناسازگار شده

۱. بلافاصله سرویس‌دهی را متوقف نکنید مگر مطمئن شوید مشکل واقعاً دیتابیس
   است (نه یک باگ اپلیکیشن).
۲. جدیدترین بک‌آپ سالم را پیدا کنید (`ls -lt /srv/arena/backups | head`).
۳. ریستور کنید:
   ```bash
   deploy/restore.sh /srv/arena/backups/dev-<تازه‌ترین>.db.gz
   ```
   این اسکریپت خودش یک نسخهٔ ایمنی از وضعیت فعلی می‌گیرد، integrity check
   می‌کند، و فقط اگر سالم بود جایگزین می‌کند.
۴. بعد از ریستور، `curl http://89.42.199.174/api/phase` و چند صفحهٔ کلیدی
   (بازار، پنل ادمین) را دستی چک کنید.

### نیاز به شروع دوباره از صفر (بازنشانی کامل بازی)

فقط در شرایط اضطراری واقعی (مثلاً یک تست/rehearsal که باید کاملاً پاک شود
قبل از رویداد واقعی). **هرگز روی دیتابیس رویداد واقعی بدون هماهنگی کامل تیم
اجرا نکنید** — این عملیات غیرقابل بازگشت است مگر از بک‌آپ ریستور کنید.

```bash
# روی سرور، داخل کانتینر migrate/tools:
docker compose run --rm migrate npx tsx scripts/reset-game.ts --yes
# یا برای حفظ تیم‌های ثبت‌نام‌شده:
docker compose run --rm migrate npx tsx scripts/reset-game.ts --yes --keep-teams
```

قبل از این کار حتماً یک بک‌آپ دستی تازه بگیرید (بالا را ببینید) — اگر
اشتباهی رخ داد، تنها راه برگشت ریستور از همان بک‌آپ است.

⚠️ **بعد از شروع فروش واقعی سکه، بازی را بازنشانی نکنید.** بازنشانی کیف‌ها را به
مقدار اولیه برمی‌گرداند و جدول `CoinOrder` را هم پاک می‌کند؛ یعنی سکه‌هایی که
بازیکن‌ها با پول واقعی خریده‌اند و سهمشان در صندوق جایزه از بین می‌رود. برای همین
اسکریپت اگر سفارش پرداخت‌شده (`PAID`) ببیند، بدون `--include-paid-orders` اجرا
نمی‌شود. اگر چاره‌ای جز بازنشانی نبود، پیش از آن فهرست سفارش‌های `PAID` را از
`/admin/coins` یا بک‌آپ استخراج کنید تا سکه‌ها را دستی برگردانید، بعد:

```bash
docker compose run --rm migrate npx tsx scripts/reset-game.ts --yes --include-paid-orders
```

### هشدار uptime دریافت شد ولی سایت از مرورگر خودتان بالاست

احتمالاً مشکل شبکهٔ مانیتور یا محل اجرای cron است، نه سرور. لاگ
`deploy/uptime-check.sh` را چک کنید و مطمئن شوید از سروری غیر از خودِ آرنا
اجرا می‌شود (طبق `docs/ops.md`، بخش ۴).
